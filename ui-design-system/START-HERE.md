# Power Web OS — Frontend handoff

**Старт здесь.** Это самодостаточная папка дизайн-системы Power Web OS для frontend-разработки. Всё, что нужно, лежит внутри — внешних зависимостей нет, кроме двух шрифтов с Google Fonts (подключаются автоматически).

> Power Web OS — white-box платформа для B2B sales / ABM: строит карту «закупочного комитета» вокруг сделки и предлагает объяснимые маршруты доступа. Интерфейс должен быть **воздушным, светлым, профессиональным — как исследовательский инструмент, а не игрушка.**

## 2 · Быстрый старт

**1. Шрифты.** Система использует **Hanken Grotesk** (весь UI) и **IBM Plex Mono** (всё числовое/машинное: скоры, confidence, домены, ID, eyebrow-лейблы). Они уже подключены через `@import` внутри `colors_and_type.css`. В проде лучше подключить через `<link>` в `<head>` или self-host для производительности:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Hanken+Grotesk:ital,wght@0,300..800;1,400..600&family=IBM+Plex+Mono:wght@400;500;600&display=swap" rel="stylesheet">
```

**2. Подключи токены.** Один импорт — и все `var(--*)` доступны во всём приложении:

```css
@import url('./colors_and_type.css');   /* или включи файл в свой бандл */
```

**3. Используй только токены.** Никогда не хардкодь hex, радиусы, тени, размеры шрифтов. Всегда `var(--token)`:

```css
.plan-card {
  background: var(--surface);
  border: 1px solid var(--border);
  border-radius: var(--r-lg);      /* карточки = 14px */
  box-shadow: var(--shadow-sm);
  padding: var(--s-5);             /* 20px */
  font: var(--body);
  color: var(--ink);
}
.plan-card:hover { box-shadow: var(--shadow-md); border-color: var(--border-strong); }
.plan-card .score { font: var(--mono); }          /* числа — моно */
.plan-card .eyebrow {                              /* структурный лейбл */
  font: var(--mono-sm); letter-spacing: .14em;
  text-transform: uppercase; color: var(--fg3);
}
```

## 3 · Семь правил, которые делают этот продукт «этим продуктом»

1. **Кобальт нормирован.** `--cobalt` — единственный заливной акцентный цвет. Появляется ТОЛЬКО на: активном маршруте доступа, **одной** primary-кнопке на экран, активном пункте навигации, ссылках и focus-ring. Если кобальт везде — его нет нигде.
2. **Stance-палитра семантична, не декоративна.** ally (зелёный) · blocker (коралл) · unsurfaced (янтарь) · neutral (серый) означают позицию человека в сделке — за / против / не выявлен. Не используй эти цвета «для красоты».
3. **Sentence case везде.** Кнопки, заголовки, меню — «Draft next move», не «Draft Next Move». Единственный UPPERCASE — это моно eyebrow-лейблы (`BOARD COVERAGE`, `WHY THIS ROUTE`).
4. **Числам нужна причина.** Любой скор/confidence/счётчик подаётся моноширинным шрифтом и рядом с обоснованием. Никогда число без причины.
5. **Без эмодзи. Без восклицательных знаков.** Пунктуация тихая; разделитель метаданных — средняя точка ` · `.
6. **Спокойное движение, без отскоков.** `--ease`, 120–360ms. Fade и небольшие сдвиги. Press = сдвиг на 0.5px вниз, никаких scale-pop. Уважай `prefers-reduced-motion`.
7. **Слегка скруглённые углы, мягкие рассеянные тени, тёплый бумажный фон.** Никаких строгих квадратов, жёстких обводок, цветных левых бордеров у карточек, градиентов-ради-градиентов, фото и иллюстраций. Единственная текстура — еле заметная точечная сетка под картой аккаунта.

Полное обоснование и тон голоса — в `design-system-readme.md` (разделы 3–5).

## 4 · Как работать с компонентами

В `app-prototype/components.jsx` и `icons.jsx` лежат **референсные** реализации (React, инлайн-стили). Это не опубликованный пакет, а эталон: открой и посмотри точные паддинги, логику hover/press и какие токены используются — потом перенеси в свой реальный стек (React + CSS-модули, Tailwind, Vue, web-components — что в проекте).

- `components-spec.md` — API каждого компонента, варианты, состояния, размеры.
- Иконки — **Lucide** (stroke, round caps, толщина 1.9–2.0, 16–18px). В прототипе вшиты как SVG-пути для синхронного рендера; **в проде ставь пакет `lucide` / `lucide-react`**, не копируй пути.
- `STANCE`-map (ally/blocker/unsurfaced/neutral → `{label,color,tint,ring}`) — заведи такую же константу у себя, чтобы stance-цвета не расползались по коду.

### Что production-ready, а что референс

| Файл | Статус | Как использовать |
|---|---|---|
| `colors_and_type.css` | ✅ Production | Импортировать как есть — это и есть слой токенов |
| `tokens/tokens.json` | ✅ Production | Скормить токен-тулингу / собрать Tailwind theme |
| `assets/logo.svg` | ✅ Production | Использовать напрямую |
| `app-prototype/*.jsx` | 🔵 Референс | Читать ради точных значений и поведения, переписать в своём стеке |
| `preview/*.html` | 🔵 Референс | Визуальная сверка глазами, не для импорта |

> ⚠️ **О шрифтах.** Hanken Grotesk и IBM Plex Mono подобраны под бриф (Google Fonts). Если у компании есть лицензионные бренд-шрифты — замените переменные `--font-sans` / `--font-mono` в `colors_and_type.css`, остальное подхватится автоматически.

## 5 · Чеклист перед сдачей экрана

- [ ] Все цвета/радиусы/тени/шрифты — через `var(--*)`, ничего не захардкожено.
- [ ] На экране ровно **одна** primary-кнопка (кобальт). Остальное — default / ghost / quiet.
- [ ] Кобальт нигде, кроме маршрута, primary-действия, active-nav, ссылок и focus-ring.
- [ ] Stance-цвета стоят только там, где есть смысл позиции (за/против/не выявлен).
- [ ] Все числа (скоры, confidence, домены, ID) — моноширинным шрифтом, рядом с обоснованием.
- [ ] Sentence case везде; UPPERCASE только у моно eyebrow-лейблов.
- [ ] Нет эмодзи и восклицательных знаков; разделитель — ` · `.
- [ ] У каждого интерактивного элемента есть видимый focus-ring (`var(--shadow-focus)`).
- [ ] Hover/press соответствуют правилам (см. `components-spec.md`); анимации без отскоков.
- [ ] Проверено при `prefers-reduced-motion: reduce`.
